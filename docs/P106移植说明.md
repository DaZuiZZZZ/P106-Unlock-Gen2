# P106-100 / P106-090 PCIe Gen2 移植说明

> 本目录新增的是 P106 移植版，原 P104 文件保持不变。
>
> 当前结论：P106-090 已在实机确认 **Gen2 解锁成功**，BAR0 镜像指纹为 `MATCH`。
> Gen3 是否可行仍取决于解锁后的 8GT/s 能力声明。
> 探针失败时不会写 GPU 寄存器。
>
> 当前生成环境是 macOS，没有 Windows 的 `csc.exe`，因此包内暂未附带编译后的
> P106 可执行文件。`build-p106.cmd` 会在目标 Windows 机器上调用系统自带的
> .NET Framework 4.x 编译器生成 `bin/P106Gen2x4.exe`。

第一份实卡读数见 [docs/P106-090-实测基线.md](docs/P106-090-实测基线.md)。

---

## 一、目标设备

| 型号 | GPU | PCI ID | 本版选择参数 |
|---|---|---|---|
| P106-100 | GP106 | `10DE:1C06` | `-dev 1c06` 或 `-dev p106-100` |
| P106-090 | GP106 | `10DE:1C09` | `-dev 1c09` 或 `-dev p106-090` |

不带 `-dev` 时程序优先寻找 P106-100，再寻找 P106-090。

`10DE:1C07` 作为旧资料中的 P106-090 兼容 ID 保留，但实卡 `10DE:1C09`
默认走 `1C09`。已确认本机 P106-90 的设备 ID 为 `10DE:1C09`。

---

## 二、从 P104 版复用了什么

P104-100 的实测流程是：

1. 写 Pascal PCIe 核的 Gen2 使能位与 5.0GT/s 请求；
2. 用 SetupAPI 禁用/启用整卡，使 PCIe 能力声明重新锁存；
3. 同时设置 GPU 端点与上游根端口的 `LNKCTL2.TLS=2`，再重训链路；
4. 常驻按住关键寄存器，掉回 Gen1 时立即补写并重训。

本移植版复用了同一套 BAR0 偏移和操作顺序：

```text
0x8841C  0x88610  0x8872C
0x8C040
0x8E110  0x8E11C  0x8E120  0x8E12C
```

同时把原先写死的 `10DE:1B87` 改为 P106-100/090 双设备识别，包括：

- PCI 总线扫描；
- Windows SetupAPI 的 Present 实例匹配；
- 写通道自检；
- NVIDIA 显卡类键 `MatchingDeviceId` 匹配；
- 计划任务、服务、安装目录和状态文件的独立命名。

---

## 三、新增的安全门禁

GP106 与 GP104 属于同一代 Pascal，但这些 BAR0 偏移不能只凭“同代”就当作已验证。
本版在每次写入前检查：

```text
BAR0 镜像 LNKCAP  == PCI 配置空间 LNKCAP
BAR0 镜像 LNKCAP2 == PCI 配置空间 LNKCAP2
```

只有两项完全一致才继续。

首次写入前还会把 8 个原始寄存器值保存到：

```text
C:\ProgramData\P106Gen2x4\registers-1C06.txt
C:\ProgramData\P106Gen2x4\registers-1C09.txt
```

卸载时按对应型号的备份精确还原，不再使用固定初值猜测。

如果输出是 `MISMATCH`：

- 不会执行 `-once`；
- 不会安装计划任务；
- 不会写驱动策略；
- 不会修改任何 GPU BAR0 寄存器。

`-status` 的只读状态查询不加载驱动，不受这项检查影响。

## 四、首次实机步骤

### 第 1 步：只读探针

在 Windows 10/11 上，右键 `probe-p106.cmd`，选择“以管理员身份运行”。

探针会自动：

1. 调用 Windows 自带的 .NET Framework 4.x 编译器；
2. 编译 `src/P106Gen2x4.cs` 到 `bin/P106Gen2x4.exe`；
3. 加载包内两个驱动；
4. 只读 PCI 配置空间和 BAR0；
5. 打印型号、设备 ID、PCIe 能力和 BAR0 指纹；
6. 同时把完整输出保存到包目录的 `probe-output.txt`。

先不要运行 `install-p106.cmd`。

### 第 2 步：检查探针输出

关键行应当类似：

```text
型号 ......... P106-100
设备 ID ...... 10DE:1C06
BAR0 镜像指纹 : MATCH
  LNKCAP  config=.... mirror=....
  LNKCAP2 config=.... mirror=....
```

同时记录以下原始值：

```text
LNKCAP
LNKSTA
LNKCAP2
LNKCTL2
BAR0 0x8841C
BAR0 0x88610
BAR0 0x8872C
BAR0 0x8C040
BAR0 0x8E110 / 0x8E11C / 0x8E120 / 0x8E12C
```

这些值用于判断 P106 的实际寄存器布局是否与 GP104 一致。

如果探针提示找不到 `1C06/1C09`，它会继续列出总线上所有 NVIDIA PCI function
及其 `SUBSYS`。把 `probe-output.txt` 发回来，可据此确认真实设备 ID 或识别
多卡/转接卡拓扑。

### 第 3 步：探针通过后执行安装

先在目标机上右键 `try-once-p106-090.cmd`，选择“以管理员身份运行”。
这个脚本只尝试一次解锁，不注册开机任务，适合作为第一次写入测试。

如果一次测试已经达到 Gen2，再右键 `install-p106.cmd` 安装常驻保持。

脚本会：

1. 再次编译；
2. 再次执行只读探针；
3. 探针失败立即停止；
4. 探针通过后部署文件、写驱动策略并注册自启任务；
5. 尝试一次解锁；
6. 打印寄存器级结果；
7. 打印状态摘要。

第一次整卡复位后可能需要 20 秒以上，让 NVIDIA 驱动重新绑定并锁存 Gen2 声明。
建议安装完成后重启，再等待 1 到 3 分钟，运行 `status-p106.cmd`。

## 五、结果判读

唯一可靠的当前速率判据是 `LNKSTA[3:0]`：

| `LNKSTA[3:0]` | 当前速率 |
|---|---|
| `1` | Gen1，2.5GT/s |
| `2` | Gen2，5.0GT/s |

不要用以下值代替当前速率：

- `LNKCAP`：卡的声明上限；
- `LNKCAP2`：支持的速率向量；
- `LNKCTL2.TLS`：目标速率请求；
- 空闲时 GPU-Z 或 `nvidia-smi` 的缓存值。

推荐同时看 GPU 端点与上游根端口的 `LNKSTA`。两端速率字段都为 `2` 才算链路真正协商到 Gen2。

---

## 六、Gen3 可行性判断

Gen3 不能只靠把速率请求改成 8GT/s 来确认。PCIe 链路速率取两端声明能力的较小值，
因此必须同时看到：

```text
LNKCAP[3:0]   >= 3   （声明上限至少 8.0GT/s）
LNKCAP2 bit3  == 1   （支持速率向量包含 8.0GT/s）
```

如果 Gen2 解锁后仍然是：

```text
LNKCAP  = 0x...42
LNKCAP2 = 0x00000006
```

说明当前锁存的能力上限就是 Gen2；继续写 `SPEED=0`、`TLS=3` 不会让链路升到 Gen3，
可行性低。

如果出现：

```text
LNKCAP  = 0x...43
LNKCAP2 包含 bit3（例如 0x0000000E）
```

才具备继续尝试 Gen3 重训的硬件声明条件。`status-p106.cmd` 和
`当前状态.txt` 会直接打印 `Gen3 8GT/s 能力`。

### 强制测试

在 P106 Gen2 稳定运行后，可以右键以管理员身份运行：

```text
try-gen3-p106-090.cmd
```

该脚本会：

1. 编译独立的 `bin\P106Gen3Test.exe`；
2. 停止 P106 Gen2 常驻任务并等待进程正常退出；
3. 在新进程内先重建或确认 Gen2；
4. 强制写 8GT/s 能力位、BAR0 镜像、`SPEED=0` 和两端 `TLS=3`；
5. 回读能力位并观察最长 5 秒；
6. 恢复 Gen2 并重新启动原常驻任务。

输出保存在 `gen3-p106-result.txt`。这是实验性强制测试，不保证成功。

---

## 七、如果探针通过但未解锁

按顺序记录：

1. 探针完整输出；
2. `-diag` 完整输出；
3. `C:\ProgramData\P106Gen2x4\status.txt`；
4. 主板芯片组、CPU、BIOS 版本；
5. 卡插在 CPU 直连槽还是 PCH 槽。

先不要反复执行 `install-p106.cmd`。整卡复位会让链路瞬断，反复复位没有诊断价值。

---

## 八、回滚

右键 `uninstall-p106.cmd`，选择“以管理员身份运行”，然后重启。

同时插着两张 P106 时，分别运行 `uninstall-p106.cmd -dev 1c06` 和
`uninstall-p106.cmd -dev 1c09`，确保两张卡的寄存器备份都被还原。

回滚会：

- 结束按住任务；
- 删除计划任务与驱动服务；
- 清除 P106-100 和 P106-090 的驱动策略；
- 按写入前保存的原始寄存器备份还原；
- 删除安装目录与状态目录。

即使主程序无法启动，仍可手动恢复：

1. 删除计划任务 `P106 PCIe Gen2 Bring-up`；
2. 删除服务 `P106Gen2x4Wr` 和 `P106Gen2x4Ts`；
3. 删除显卡类键中的 `RMPcieLinkSpeed`、`RmForceEnableGen2`、`RmEnableGen2`；
4. 重启。

---

## 九、当前限制

- 当前版本一次只管理一张卡；同时插 P106-100 和 P106-090 时，用 `-dev` 选择其中一张。
- P106 的 BAR0 偏移尚未经过实机写入验证，探针 `MATCH` 是继续实验的最低门槛。
- 不建议把 P106 版直接套到 P102、P104 或其他 GP10x 型号。
- 不要同时运行其它 WinRing0 / ThrottleStop 工具。
- 需要关闭 Windows“易受攻击的驱动程序阻止列表”，这会降低系统防护等级；用完应卸载并重新开启。
- 任何直接写 PCIe/GPU 控制寄存器的工具都有掉卡、黑屏或需要重启的风险。首次实验应在可恢复的机器上进行。
